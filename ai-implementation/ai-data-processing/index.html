AI Data Processing

Cleaning and matching data at a scale people cannot manage manually.

What is ai data processing?

AI data processing cleans and standardises your records, matches the same entity across different systems, fills gaps where a reliable source exists, and runs on a schedule so the data stays clean rather than drifting back within months.

Messy data blocks work that would otherwise be straightforward. The same customer recorded five ways, phone numbers in four formats, addresses that do not match between the sales system and the delivery system.

Cleaning it once is a project. Keeping it clean is the part most businesses skip, which is why the same cleanup gets commissioned again eighteen months later.

We clean, standardise and match, then run it as a scheduled job so new records are corrected as they arrive rather than accumulating into the next backlog.

Who Duara is

Duara handles data cleanup from Nairobi, frequently after a migration, a merger, or the discovery that two departments have been reporting different customer counts for years.

We treat uncertain matches as items for review rather than merging them, and we keep every change reversible. Merging two genuinely different customers is far more damaging than leaving a duplicate in place, and that asymmetry drives every threshold we set.

Problems this solves

These conditions usually follow a system change, and they compound quietly until somebody tries to report across the whole business.

  • error One entity recorded many times. The same customer exists under several spellings, so history is fragmented and totals are wrong in a way nobody can quantify.
  • error Formats that never agreed. Phone numbers, dates and addresses were entered differently by different people over years, so matching fails on technicalities.
  • error Systems that disagree. Sales and delivery hold different addresses for the same customer and neither is marked as authoritative.
  • error Cleanups that do not last. A cleanup project completes, nothing changes about how records are created, and the mess returns within two years.

Technologies we use

  • memory Fuzzy matching. Identifying records that describe the same entity despite spelling, spacing and format differences.
  • memory Format standardisation. Normalising phone numbers, dates, names and addresses to a consistent form across systems.
  • memory Cross system linking. Establishing which record in one system corresponds to which in another, with confidence recorded.
  • memory Change journaling. Retaining original values so every correction and merge can be reversed.
  • memory Scheduled execution. Running as a recurring job so new and changed records are processed continuously.

Threshold setting is the whole job. Too aggressive and real customers get merged; too cautious and the review queue is unusable. We tune it on your data with you.

Frequently asked questions about ai data processing

Could it merge two real customers by mistake?

Uncertain matches are held for review rather than merged. Combining two genuinely different customers is far more damaging than leaving a duplicate, and thresholds reflect that.

Is the original data kept?

Yes. Every change is journaled with the original value, so any merge or correction can be reversed without restoring a backup.

Do we see changes before they apply?

Yes. A dry run produces the proposed merges and corrections with counts, so you see the consequences before anything is altered.

Who sets the matching thresholds?

You do, with our recommendation. Your team knows which differences between records are real and which are typing variation.

Does it handle Kenyan phone formats?

Yes, including the several ways the same number gets stored, which is one of the most common causes of duplication here.

Why does the cleanup need to be scheduled?

Because a one off clean without ongoing maintenance simply defers the problem. The mess returns within about two years.

How long does the initial clean take?

Four to six weeks, after which it continues as a recurring job rather than ending.

What is a golden record?

The single agreed version of an entity, assembled from the best available fields across the duplicates being merged.

Can it match records across different systems?

Yes, and cross system linking is usually where the largest reporting discrepancies get resolved.

What if two systems disagree about a value?

Precedence rules are agreed with you, so one system is authoritative for each field rather than the conflict being resolved arbitrarily.

Will gaps be filled automatically?

Only where a reliable source exists, and the source is recorded against the value so nobody treats an inference as verified.

Should we start with part of the data?

Yes, and we recommend it. Running against one region or product line first proves the matching rules before they touch the whole set.

Does this help before a system migration?

Considerably. Clean matched data is the difference between a migration that works and one that produces months of corrections afterwards.

How do we know it is working?

Quality reporting tracks duplication and completeness over time, so both the improvement and any later drift are visible.

Is our data sent anywhere?

Processing happens within your environment, and records are never used to train public AI models.

What about records with no unique identifier?

Those are the hard cases and fuzzy matching handles them, though more of them land in review, which we report honestly.

Can it detect records that have gone stale?

Yes, such as contacts who have almost certainly changed employer, which is a common and rarely tracked source of wasted effort.

Who should be involved from our side?

Whoever knows the data best, usually operations rather than IT, since they know which differences are meaningful.

Does it work with data in Swahili?

Yes, including name and address conventions that generic matching handles poorly.

What does it cost to run?

Record count and processing frequency set the cost, quoted against your own data volumes before work begins.

Glossary of terms

Data quality terms in plain language.

Deduplication
Finding records that describe the same thing and combining them into one.
Fuzzy matching
Matching records that are similar but not identical, allowing for spelling and format differences.
Golden record
The single agreed version of an entity, assembled from the best fields across duplicates.
Normalisation
Converting values into a consistent format, such as one standard way of writing a phone number.
Data drift
The gradual return of inconsistency as new records are created without controls.
Change journal
The record of what was altered and what the original value was, enabling reversal.
