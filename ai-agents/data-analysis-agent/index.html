Data Analysis Agent

Ask a question in plain words and see exactly how the answer was worked out.

What is data analysis agent?

A data analysis agent turns a question asked in ordinary language into a query against your own data, returns the answer, and shows the query and figures it used so anybody can check how the number was reached.

Most businesses have the data and cannot reach it. The question is simple, the answer sits in a database, and getting it requires somebody who writes SQL and has three other things to do first.

So the question goes unasked. Decisions get made on the monthly report, which answers last month questions rather than this morning ones.

An agent lets somebody ask directly. The important part is that it shows its working: the query it ran, the rows it counted, the filters it applied. A number nobody can check is not analysis, it is a rumour with a decimal point.

Who Duara is

Duara builds data analysis agents from Nairobi for businesses whose questions currently queue behind whoever knows the database.

We refuse to hide the query. Every tool in this category can produce a confident number, and the ones that do not show their working are the dangerous ones, because a wrong answer presented cleanly is indistinguishable from a right one until somebody acts on it.

  • error Figures nobody can trace. A number appears in a board pack and no one present can say how it was calculated.

Frequently asked questions about data analysis agent

Can anyone use it or only analysts?

Anyone. Questions are asked in ordinary language, which is the point, though the working shown alongside is there for whoever wants to check it.

How do we know the answer is right?

Check the working. Every answer returns the query, filters and row counts, so the calculation is verifiable rather than trusted.

What if it gets something wrong?

The visible query is how you find out. This is exactly why we refuse to hide it, since a wrong answer presented cleanly looks identical to a right one.

Will it make up numbers?

It declines where your data cannot answer the question rather than producing a plausible figure. That refusal is a deliberate design choice.

Can it change our data?

No. Access is read only, so a badly phrased question cannot alter or delete anything.

Why do our reports disagree today?

Usually definitions rather than technology. Two reports count active customers differently, which is why defining measures comes before connecting data.

What data can it use?

Databases, spreadsheets and business systems you connect. It answers from your data, not from general knowledge.

Does it work if our data is messy?

Up to a point, and we report where it is too inconsistent to answer reliably rather than automating on top of it.

How soon can we start asking questions?

Four to six weeks, with measure definitions normally taking longer than the data connection.

Can it produce charts?

Yes, where a chart communicates better than a number, though the underlying figures stay available.

Can we schedule regular questions?

Yes. Anything you ask weekly can arrive automatically instead of being asked each time.

Does it replace our BI tool?

No. It answers ad hoc questions that would otherwise queue. Dashboards still do the job of showing the same measures repeatedly.

Who can see which data?

Permissions follow your existing access rules, so it cannot show somebody data they could not already reach.

Can it explain why a number moved?

It can show what changed in the underlying data. Why it changed commercially is a judgement it does not attempt.

Does it work across several systems?

Yes, though joining systems reliably depends on shared identifiers, and we test that before promising it.

Is our business data confidential?

Yes. It stays in your systems, is queried in place, and no public AI model is trained on it.

Can it forecast?

Basic trend projection, yes, clearly labelled as projection. Anything more serious is a separate piece of work.

What if two people ask the same question differently?

Agreed measure definitions are what make the answers match, which is the main reason that step exists.

Do we still need an analyst?

For anything requiring judgement, yes. This removes the queue for routine questions, which frees analysts for the harder work.

What is the ongoing cost of query access?

Query volume and data size determine it, quoted against your own usage before anything is agreed.

Glossary of terms

Data terms in plain language.

Query
The instruction sent to a database to retrieve specific data.
Measure definition
The agreed meaning of a business term, such as what makes a customer active.
Read only access
Permission to look at data without the ability to change it.
Data quality
How complete, consistent and accurate your records are, which sets the ceiling on any analysis.
Schema
The structure of your database, including what tables exist and how they relate.
Working
The query and figures behind an answer, shown so the result can be verified.
