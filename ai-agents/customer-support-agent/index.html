Customer Support Agent

Handles the routine tickets completely, so your team only sees the ones that need them.

What is customer support agent?

A customer support agent is software that resolves support cases end to end rather than drafting replies for somebody else to send. It looks up the account, performs the action, answers the customer and closes the case, within limits you define.

Most support queues are mostly repeat work. Where is my order, how do I reset this, what are your opening hours, has my payment gone through.

An agent closes those itself. It checks the order, verifies the account, sends the answer and marks the case resolved. The distinction from a chatbot is that it takes action rather than only producing text.

When a case genuinely needs a person, it hands over with everything already gathered, so your team does not open the ticket and begin by asking the customer to explain again.

Why we start with the narrowest case list

Duara deploys support agents from Nairobi for businesses whose ticket volume is dominated by a handful of repeating case types.

We start with the narrowest possible set of case types and widen it only on evidence. An agent given broad permissions on day one will eventually close something it should have escalated, and the resulting complaint costs more trust than the extra automation saved.

How the process works, step by step

A support agent usually resolves its first live cases within four to five weeks, starting from a deliberately narrow scope.

  1. Step 1

    Free ticket analysis

    We examine your case history to identify which types are genuinely repetitive and safely automatable.

  2. Step 2

    Narrow scope agreed

    We pick the two or three highest volume, lowest risk case types to start with rather than everything at once.

  3. Step 3

    Shadow resolution

    The agent proposes resolutions that a person approves, which measures accuracy before it acts alone.

  4. Step 4

    Live on the narrow set

    It closes cases in the approved types, with every action logged and reviewed weekly.

  5. Step 5

    Widening on evidence

    Additional case types are enabled one at a time where the performance data supports it.

Frequently asked questions about customer support agent

How is an agent different from a chatbot?

A chatbot produces text. An agent performs the lookup or the update and closes the case. It takes action rather than describing one.

What stops it closing something it should not?

It only handles case types you have explicitly approved, and starts with two or three. Everything outside that scope escalates automatically.

Why start so narrow?

Because an agent with broad permissions on day one will eventually close something that needed a person, and that complaint costs more trust than the extra automation saved.

Can we see what it did?

Yes. Every action is logged in plain language, showing what it did and to which account, without needing a technical query.

What if it makes a mistake?

You disable that case type immediately without stopping the whole agent, and the action log shows exactly which cases were affected.

Does it work inside our helpdesk?

Yes. Cases and history stay in the system your team already uses rather than moving somewhere new.

What is shadow mode?

The agent proposes a resolution and a person approves it. That phase measures accuracy before it is allowed to close anything alone.

How long before it closes real cases?

Four to five weeks, including the shadow period, which is the part we will not shorten.

Can it access customer accounts?

It has read access to what it needs and change permission only where you have explicitly granted it. Everything else is read only.

What happens when a customer is furious?

Sentiment triggers route the case to a person before the agent attempts anything.

Can it support customers in Swahili?

Yes, including messages that mix English and Swahili, which is common in customer support here.

How much of our volume can it close?

It depends entirely on how repetitive your cases are. The ticket analysis gives you the number before you commit to anything.

Can it issue refunds or credits?

Only within limits you set, and most clients keep those with a person. Money movement is the last thing we would automate.

Does it learn from resolved cases automatically?

No, and deliberately. Learning from unreviewed resolutions is how agents acquire bad habits. Changes to behaviour are approved by you.

What is the resolution rate we should expect?

It varies by case type, which is why we report it per type rather than as one figure that hides the weak categories.

Does it replace support staff?

It absorbs repeat volume. Most clients keep their team and handle growth without hiring, rather than reducing headcount.

Can it work across email and chat?

Yes, wherever your helpdesk receives cases, using the same scope and permissions across channels.

Who monitors it?

Somebody reviews the weekly action log at first. Once case types settle, monthly review is usually sufficient.

Is customer data used for training?

No. Case data stays in your systems and is never used to train public AI models.

How much does a support agent cost monthly?

Case volume drives it, quoted against your own ticket counts before any build is agreed.

Glossary of terms

Support agent terms as used here.

Agent
Software that carries out a task in your systems, as distinct from a chatbot that only produces text.
Case type
A category of support request, such as order status or password reset, enabled individually for automation.
Resolution rate
The proportion of cases closed without a person, measured separately for each case type.
Escalation
Passing a case to a person, either by rule or because the agent judged it beyond its scope.
Scope
The explicit set of actions an agent is permitted to take, with everything outside it forbidden.
Shadow mode
The agent proposing actions for human approval rather than performing them directly.
